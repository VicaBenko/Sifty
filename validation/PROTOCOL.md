# שער אימות — Sift

מבחן שנועד לענות על שאלה אחת, לפני שנכתב PRD או שורת קוד:

> **האם תיוג אוטומטי מזהה נכון אובייקטים קטנים בתמונות אמיתיות מהגלריה שלי, ברמה שמאפשרת מחיקה לפי תיאור?**

**קריטריון מעבר:** כיסוי ≥ 80% ודיוק ≥ 80% על השאילתה "דף + עט + אייפד".
**עלות משוערת:** פחות מדולר ל-500 תמונות. **זמן:** יום עבודה, רובו סימון ידני.

---

## בטיחות — מה הסקריפטים עושים ולא עושים

| | |
|---|---|
| ✅ קוראים מהגלריה | |
| ✅ מייצרים עותקים מוקטנים בתיקיית עבודה נפרדת | |
| ❌ **לא מוחקים** שום דבר | |
| ❌ **לא מעבירים** שום קובץ | |
| ❌ **לא כותבים** לתיקיית iCloud | |

תיקיית העבודה נוצרת מחוץ לתיקיית iCloud, וניתן למחוק אותה בסוף בלי שום השפעה על הגלריה.

מה שנשלח לשרת: **גרסאות מוקטנות ל-384 פיקסל בלבד** — מספיק לזיהוי אובייקטים, לא מספיק כדי לשמש כתמונה. המקורות לא עוזבים את המחשב.

---

## התקנה

נדרש Python 3.10 ומעלה.

```
pip install -r requirements.txt
```

מפתח API — ב-PowerShell:

```
$env:ANTHROPIC_API_KEY="sk-ant-..."
```

או ב-CMD:

```
set ANTHROPIC_API_KEY=sk-ant-...
```

## לפני שמתחילים — הורדת התמונות

תמונות iCloud ב-Windows הן *placeholders* עד שמורידים אותן. סקריפט הדגימה מזהה את זה ומתריע, אבל עדיף להקדים:

ב-File Explorer, בתיקיית iCloud Photos → בחירת הכל → קליק ימני → **"Always keep on this device"** → להמתין לסיום ההורדה.

---

## ארבעת השלבים

### 1. דגימה

```
python step1_sample.py --source "C:\Users\<user>\Pictures\iCloud Photos\Photos"
```

דוגם 500 תמונות אקראיות ומייצר עותקים מוקטנים ב-`_sift_workspace/thumbs/`.
ניתן לשנות: `--count 300`, `--seed 7`.

### 2. תיוג

```
python step2_tag.py --limit 20     # קודם ניסיון קטן, לוודא שהכל עובד
python step2_tag.py                # ואז המלא
```

שולח כל תמונה לתיוג ושומר ב-`catalog.json`. **ניתן לעצירה והמשך** — הרצה חוזרת מדלגת על מה שכבר תויג.

### 3. סימון ידני

```
python step3_label.py
```

מייצר `_sift_workspace/label.html`. פותחים בדפדפן, ולכל שאילתה בנפרד סורקים את רשת התמונות ולוחצים על אלה שבאמת מתאימות.

> **חשוב: אין להסתכל על `catalog.json` לפני סיום הסימון.** אם רואים מה המודל ענה, הסימון מוטה והמבחן מאבד את ערכו.

הסימון נשמר אוטומטית בדפדפן, אז אפשר לעצור ולחזור. בסוף — לחיצה על כפתור השמירה, והעברת `ground_truth.json` מתיקיית ההורדות לתיקיית העבודה.

### 4. ציון

```
python step4_score.py
```

מדפיס לכל שאילתה כיסוי ודיוק, ופסק דין מול קריטריון המעבר.

## שלוש השאילתות ולמה דווקא הן

| שאילתה | תפקיד |
|---|---|
| **דף + עט + אייפד** | **המבחן האמיתי.** שלושה אובייקטים קטנים וחיבור משולש — המקרה הקשה ביותר |
| שולחן + טלוויזיה | בקרה. שני אובייקטים גדולים. אם גם זה נכשל, הבעיה בסיסית ולא בחיבור |
| דף בלבד | רצפה. אובייקט קטן יחיד בלי חיבור. מבודד: הבעיה בזיהוי אובייקטים קטנים או בחיבור ביניהם? |

שלושתן יחד מאבחנות *איפה* נשבר, לא רק *אם*.

## איך לקרוא את התוצאה

**עבר** — ההנחה שהמוצר נשען עליה מאושרת. ממשיכים ל-PRD.

**נכשל, אבל הבקרה עברה** — הזיהוי הבסיסי עובד וההרכבה נשברת. לפני שמסיקים מסקנות, לבדוק בדוח את התמונות שפוספסו:

- אם התיוג כתב `notepad` והשאילתה חיפשה `paper` — **זו בעיית נרדפות, לא בעיית זיהוי.** מוסיפים את המילה ל-`queries.json` ומריצים שוב את שלב 4 בלבד. זו הרצה של שניות ובלי עלות.
- אם התיוג פשוט לא ראה את העט — זו בעיית זיהוי אמיתית. שווה לנסות מודל חזק יותר דרך `--model` לפני שנוטשים.

**נכשל גם בבקרה** — משהו שבור בהגדרות, לא במוצר. לבדוק שהתמונות המוקטנות תקינות ושהתיוג מחזיר תוכן.

**נכשל בכל הווריאציות** — חוזרים ל-Correct Course. ייתכן שהמוצר יצטרך להצטמצם לקטגוריות רחבות ובולטות בלבד. עדיף לדעת עכשיו.
